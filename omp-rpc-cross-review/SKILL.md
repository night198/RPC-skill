# RPC 交叉审核版

调用 `/skill:omp-rpc-cross-review`，并提供目标项目、任务和审查参数。本版独立安装，不依赖普通版，不修改普通版；普通版按风险选择独立审查，本版强制异模型独立审查。它提供调度方法，不包含自动调度程序或后台守护服务，不保证主控退出后继续推进。

## 1. 每批必填的审查参数

| 参数 | 来源与要求 |
|---|---|
| `review_provider` | 用户指定的当前 OMP 供应商 ID，不能用品牌名称猜配置 ID |
| `review_model` | 用户指定的完整模型 ID；与 provider 分开记录，不猜简称或别名 |
| `review_thinking` | 用户指定的思考强度；须为当前模型及 OMP 接口实际支持的值 |

这些是调用参数，不是安装占位符。禁止把某家供应商、模型或强度写成默认值。安装无需选择审查模型，开始任务前必须确认。

参数来源顺序：本次用户明确指令 → 同一项目同一批次已确认台账。部分覆盖仅更新明确指定项，保留其余已确认项并复核组合；用户指令冲突或含糊时先问清。不从另一个项目/批次或开发模型推断审查配置。空值、示例占位文字及“随便选”不算参数已确认。

缺少任何参数时，一次询问所有缺失项，例如：“请补充本批审查供应商 ID、完整模型 ID 和思考强度；已有明确值无需重复提供。”先确认再派发开发或审查任务；允许主控进行必要的只读环境核对。用户只给了模型时，不能擅自补供应商或强度。参数不支持时说明不支持的项并请用户选择替代，不静默降级或换渠道。不支持可调思考强度的模型，须由用户明确确认使用该模型的不可调模式，记录 `review_thinking=not-applicable`，经实际能力核对后不发送思考设置；该标记不是传给 OMP 的值。

明确任务、供应商和模型的调用授权及费用范围后再启动收费任务；已有明确授权不重复询问。不得替用户新增账户、开通付费渠道、读取/复制密钥或私有模型配置正文。

## 2. 异模型准入与恢复复核

主控先取得自身和全部开发会话的实际 provider/model、底层模型身份及证据。优先用运行时状态、非秘密能力元数据和可信映射；缺失时询问用户，不猜主控模型。启动任何新开发会话前也要核对。

审查模型的底层身份必须与主会话及所有参与本批实现的开发模型不同。开发模型之间可相同；审查供应商不必不同。仅改变供应商别名、路由、思考强度或 Fast 不构成异模型；不同供应商提供同一底层模型也不合格。不同模型系列可减少共同盲点，但不作为硬性条件，也不保证正确性。

无法确认底层身份时，说明“异模型关系未验证”，请用户确认实际映射或换用可核实模型；用户确认的映射标注为用户提供，不冒充运行时证明。明确相同则请用户重新选择审查模型，不把接受风险当作满足异模型门禁，不悄悄切回普通版。

使用前按 [RPC 连接参考](references/rpc-control.md) 核对可用性、实际模型与思考强度。仅模型出现在列表中不能证明服务已成功响应；首次真实审查失败仍记失败。403、限额、模型不可用或参数不匹配时暂停受影响任务，报告并等待用户裁定，不自动重试收费调用或换模型。

每次启动、恢复、换模型或增加开发会话都复核参数与异模型关系。开发模型历史集合保留本批曾参与实现的模型，关闭会话不移除其身份。若模型变化导致关系不再满足，暂停新的开发/审查派发，保留当前现场，由用户选择新审查模型；对受影响产物重新审查。已确认参数同批可复用，不每片重复询问。

## 3. 角色与配置边界

- 主会话：核对源码、定需求/架构/Spec、拆片和分配所有权、管理 RPC、裁决发现、集成、集中冒烟及最终验收；唯一与用户沟通和派发任务的控制者。
- 开发 RPC：按冻结契约实现指定片，输出实际差异、静态证据与未验证项；不自行改公共契约、调度其他会话或批准自己的任务。
- 审查 RPC：独立 session，按稳定版本只读检查，报告问题与证据；不改业务代码或正式台账，不派修正任务，不批准发布。主控不得用自查代替本版必要的异模型审查。

开发模型及模式沿用用户本批授权或可信项目设置，无法确定才询问；本版不指定开发模型默认值。审查仅使用确认的三个参数，不能继承开发模型、思考强度或开发专用 Fast 要求。未指定审查 Fast/服务档位时不主动设置；核对实际继承值，如不兼容、导致已选参数无法生效或超出费用授权，则停下询问，不自动修改。扩展默认不加载，必要扩展逐项授权；保留项目规则与开发所需工具，实际 dumpTools 必须核对。提示词和工具清单不等于系统沙箱。

窗口大小和扩展上下文沿用用户环境，不设置固定容量、不强制开关、不作为准入门禁，也不改全局默认配置。提交、推送、建仓库、部署及生产重启各自需要授权。删除按当地可恢复策略进行。

## 4. 功能优先与并发切片

顺序：按架构完成真实功能闭环 → 集中冒烟确认跑通 → 按实际使用环境补强必要边界 → 对受影响路径定向回归。功能是一个用户可观察的输入到结果，不是整个项目，也不能缩成一个函数。不以 mock、占位返回或假成功宣称接通。

主控冻结功能 id、真实入口/结果、架构与依赖、接口/字段/错误语义、使用环境和冒烟标准。每片写明所属功能、Spec 版本、允许文件/符号、静态接收标准、证据要求、允许命令和停止点。任务不让开发会话自行选择未确定的架构。

开发期间以静态审查核对功能、架构、契约、调用方和数据流，不每次编辑或每片启动服务、跑冒烟、全套测试/构建/格式化。必要的最小类型检查可按具体不确定性执行；只有用户明确要求、项目强制规则或会阻塞后续实现的具体运行不确定性，才提前做最小定向实验并记录理由。RPC 状态检查是调度检查，不是功能冒烟。

本版在派发实现前必须完成冻结方案的独立审查；每片完成后必须通过异模型静态审查，主控处置当前阶段阻断发现并集成后记“静态接收”，即可解锁依赖片。功能齐备后独立审查跨片接口与组合行为，主控集中运行冒烟。只读静态接收不能标记功能已通过。

并发数量按本批就绪任务、资源与费用授权确定，不固定写死；审查进程占同一额度，预留名额。额度不足时先保存并安全关闭 settled 的空闲开发进程再开审查，不自动扩容。独立切片可同时开发，审查积压时优先消化结果。不得递归开会话或使用 task 子 Agent 替代独立 RPC。

依赖图先冻结；前置片静态接收并集成后才派消费者，明确基线未运行验收。同工作树同一文件只允许一个写入者，包括锁文件、生成物、配置和格式化输出。禁止读另一会话正在修改的输入；工作树/快照隔离不能替代数据库、端口、缓存等资源隔离。主控统一串行集成共享目标。失联/结果未知时保留所有权并阻塞受影响下游，只有确认独立的分支可继续。

## 5. 独立审查与最终验收

审查输入包括 Spec、阶段、基线、候选版本、差异、必要调用方/配置、验收标准和证据。用提交或完整输入快照及哈希固定对象；审查期间不得写入该对象，其他不相关范围可继续开发。候选或契约变化使相关结论失效，重新审查受影响范围。不把开发自评或整份 transcript 当成事实前提。

审查优先功能与架构，分别执行方案、切片静态、功能集成审查。每个发现记录 id、阶段、候选版本、严重程度、文件/符号/行号、违反契约或具体失败场景、证据/复现条件、建议范围及已验证/推断/未验证状态。安全建议需有真实暴露面和使用环境适用依据，通常列入功能跑通后的清单，不能用泛化风险阻塞功能主线。

现有保护、必要正确性、凭据/真实数据隔离和不可逆操作授权不为提速省略；公网、多租户或敏感环境所需保护在实际暴露前落实。无适用依据的加固建议记不适用，不实现、不阻断。审查默认不执行会写缓存/数据库/生成物的命令；必要复现由主控授权隔离环境，并遵守功能级验证节奏。

主控逐项记录采纳、驳回依据、后置安排或待用户裁定。当前阶段必需审查未完成、审查失败或真实阻断项未解决时，不静态接收受影响片；不得将“不同模型同意”或多数投票当成正确性证据。修正派给原所有者，新版本复审。分歧按源码与证据裁决；涉及需求、费用、风险接受交用户。

完整功能由主控集中冒烟，UI 看实际页面，CLI/API 看真实输入输出及状态。失败只修相关范围、定向重跑。冒烟通过但必要环境加固未完成时记“待加固”；完成加固及受影响路径回归后才能记功能通过，不自动授权发布。审查模型不同不能代替行为验收。

## 6. 进度、上下文与精确恢复

使用 [批次台账](references/session-record.md) 记录确认来源、模型身份集合、每片状态、审查发现、功能状态和精确恢复现场，保存在项目外私有目录。只有主控更新正式记录，不另建重复台账。

派发前、完片后和大量输出后读取实际 contextUsage.percent；缺失先核对当前接口，仍不可解释时暂停新派发，不当作零。按本批已确认的整理阈值/环境策略在 settled 边界 shake；compact 前写交接，完成后查真实结果和占用，失败不算完成。需要调度阈值但当前无策略时集中确认，不硬编码窗口或数字上限。压缩不扩大授权，恢复后重传有效 Spec、所有权和门禁。

换新会话读取有效交接并复核参数；精确恢复使用原 sessionFile，不能混用最近会话。失联不重放可能已执行的写操作，未确认旧写入者停止前不启动第二个写入者。控制端内核丢失不能凭 PID 宣称重新持有旧 stdin。退出主控时报告剩余工作，不宣称后台自动推进。

## 7. 安装与调用

复制完整 `omp-rpc-cross-review` 目录到当前 OMP 实际 Skills 目录。已有安装先比较和备份；本版无需改写安装参数，不覆盖普通版。新开/重新加载会话后确认发现 `skill:omp-rpc-cross-review`。原版安装表不适用于本版。

```text
/skill:omp-rpc-cross-review
目标项目：<项目路径>
任务：<完整功能目标>
review_provider: <OMP供应商ID>
review_model: <完整模型ID>
review_thinking: <该模型支持的思考强度>
```

尖括号表示调用示例，必须由用户真实选择替换。只安装和做无模型调用发现检查时不要求审查参数；未提供参数的首次开发调用必须触发询问，不先做收费审查或启动开发。
