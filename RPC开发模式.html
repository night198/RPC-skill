Skill 不绑定窗口容量或扩展上下文开关。模型窗口调整后，无需为此修改 Skill；不自动更改你的设置。
  1. 派发前 / 完片后读取实际占用，给下一片留余量。
  2. 到清理阈值空闲边界 shake，减少已读工具输出。
  3. 到压缩阈值先保存交接，再 compact，核对结果。
  4. 到停止阈值暂停派新片；压缩不足就换新会话。

整理阈值独立配置，与窗口容量分开。压缩前保存进度与交接，恢复后仍须核对源码及验收证据。

04

换来可持续开发，也多一份管理工作

收益

  • 比通常按任务派发的子 Agent 更便于跨片延续状态。
  • 主控可回查开发过程，审查、复盘和验证有依据。
  • 中断、压缩、换会话后，沿进度与交接恢复。
  • 用户可看到已完成、待验收和阻塞，而非只看聊天。

代价与边界

  • 必须维护进度与交接；过期文档会误导恢复。
  • 要处理管道、权限、进程、请求 id 和上下文。
  • 压缩可能遗漏；不能承诺零遗忘或零错误。
  • 主控退出后不保证继续；超时写操作不能盲重发。

适合：跨天、多阶段、需审查的项目。小改动直接完成通常更省事。子 Agent 的历史保留能力因实现而异。
