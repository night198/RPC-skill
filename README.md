# RPC 开发模式 · OMP Skill

主会话通过 OMP 原生 stdin/stdout JSONL RPC 驱动独立开发会话，负责冻结 Spec、拆片、审查、行为验收、上下文管理和恢复。用户只在主控窗口沟通，执行会话完成指定切片后停止。

本仓库提供 **Skill 文档与安装模板**，不包含自动调度客户端或后台守护服务。模板未初始化时不能派发开发任务。

## 安装

1. 下载或克隆完整仓库，先让安装 Agent 阅读初始化安装说明。
2. 核对本机 OMP 版本、可用模型、模式、Skills 发现目录和配置作用范围。
3. 确认全部 8 项参数，再将完整 `omp-rpc-dev` 目录复制到实际 Skills 目录。只在安装副本中替换占位符；保留仓库模板。
4. 已有安装先比较和备份。验证参数、链接、Skill 发现和真实 RPC 状态后再启用。

给安装 Agent 的提示：

> 请阅读 RPC开发模式-Agent初始化安装说明.md，先核对本机 OMP 环境，引导我确认模型、模式、上下文整理阈值及安装位置，再初始化并安装 omp-rpc-dev。窗口大小和扩展上下文沿用我的设置，不要修改。不要启动业务开发、改全局默认模型或生产环境；涉及持久化设置和模型测试费用先让我确认。

安装后，在主控窗口调用 `/skill:omp-rpc-dev`，或明确要求使用 `omp-rpc-dev` 开发指定项目。

## 功能优先与验证节奏

按架构完成真实功能闭环，再集中冒烟确认跑通，随后按实际使用环境补强必要安全边界，并只回归受影响路径。开发中以静态审查为主；实现切片经静态接收并集成即可继续依赖片，不每改一片就启动服务或重复冒烟。静态接收与功能运行通过分别记录。

审查优先检查功能、架构和数据流；安全建议须有实际暴露面与适用依据，通常放在功能跑通之后处理，不让假想风险衍生出通用安全框架。必要正确性、现有保护、凭据与真实数据隔离及授权仍保留；公网/敏感环境所需保护须在真实暴露前完成。提前运行实验只用于明确的阻塞性不确定性、用户要求或项目强制规则。


## RPC 并发与独立审查

主控可把已解耦的任务派给多个独立 RPC 会话同时执行。先冻结公共契约、依赖和文件/资源所有权，只运行已就绪切片；公共前置实现经主控静态接收并集成后解锁下游，完整功能统一冒烟。同文件写入、共享测试资源及集成操作不能靠多开会话规避冲突。

独立审查按风险启用：跨模块契约、共享状态、事务、权限或复杂集成建议增加审查 RPC；小而独立的改动可由主控审查。审查会话检查派发方案、稳定候选改动和集成后的跨片行为，只报问题与证据，不直接修改或调度。主控保留需求裁决、派发、集成和最终行为验收责任。

并发上限、费用授权和审查门禁按开发批次记录，审查会话计入并发额度；无需新增安装占位符。全部会话遵守同一初始化、上下文和恢复约束。具体准入与角色边界见 [Skill 第 2 节](omp-rpc-dev/SKILL.md)，批次状态见 [台账模板](omp-rpc-dev/references/session-record.md)。

启动示例：

> 使用 omp-rpc-dev 的 RPC 并发模式。先核对依赖与文件/资源所有权，确认本批并发额度和费用授权；对高风险契约及集成启用独立只读审查。由主会话统一派发和最终验收，不让执行或审查会话递归调度。

离线学习页演示切片静态接收与交接；完整功能才集中冒烟。并发、独立审查和环境加固规则以 Skill 和参考文档为准。本包提供调度方法，不包含自动并发调度器。

## 运行约束

- 主控按完整功能组织实现切片；切片静态接收并集成后推进依赖，完整功能统一运行验收，适用加固完成后才记通过。
- 精确恢复使用原 sessionFile；需要减小上下文时另开会话并读取有效交接。超时写操作不能自动重发。
- 上下文窗口大小和扩展上下文由用户控制，Skill 不规定固定容量或开关，不将其作为安装参数或运行门禁。占用百分比的清理/压缩阈值独立配置。
- RPC 参考来自 OMP 18.8.7；原制包记录核对了 18.9.0 CLI。安装时仍须检查当前版本接口，历史通过不能代替当前验收。
- 提交、推送、创建远程仓库、部署和生产重启需要各自授权；不会因为启用 Skill 自动获准。
