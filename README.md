# RPC 开发模式 · OMP Skill

主会话通过 OMP 原生 stdin/stdout JSONL RPC 驱动独立开发会话，负责冻结 Spec、拆片、审查、行为验收、上下文管理和恢复。用户只在主控窗口沟通，执行会话完成指定切片后停止。

本仓库提供两个可独立安装的 Skill，不包含自动调度客户端或后台守护服务。普通版先初始化安装模板；交叉审核版在调用时确认审查参数。两版都在各自门禁满足后才派发开发任务。

## 两个版本怎么选

| 项目 | 普通版 `omp-rpc-dev` | 交叉审核版 `omp-rpc-cross-review` |
|---|---|---|
| 独立审查 | 按风险启用，低风险可由主控审查 | 必须由独立 RPC 审查方案、切片和功能集成 |
| 审查模型 | 不强制异模型 | 必须不同于主会话及本批所有参与实现的开发模型 |
| 参数来源 | 安装副本确认 8 项运行参数 | 调用时提供 `review_provider`、`review_model`、`review_thinking`；缺项主动询问 |
| 安装 | 复制并初始化 `omp-rpc-dev` | 直接复制完整 `omp-rpc-cross-review`；不依赖普通版、不套用其安装参数表 |
| 调用 | `/skill:omp-rpc-dev` | `/skill:omp-rpc-cross-review` |
| 适合场景 | 按任务风险控制审查成本 | 明确需要异模型视角并接受额外审查调用的任务 |

两版可同时安装，每批明确选择一个，不叠加两套调度规则。共同遵循功能优先、开发期间静态审查、完整功能集中冒烟和按实际环境加固；上下文窗口由用户控制。异模型不等于正确性保证，最终验收由主会话负责。

## 安装与调用

### 普通版

1. 下载或克隆完整仓库，先让安装 Agent 阅读初始化安装说明。
2. 核对本机 OMP 版本、可用模型、模式、Skills 发现目录和配置作用范围。
3. 确认全部 8 项参数，再将完整 `omp-rpc-dev` 目录复制到实际 Skills 目录。只在安装副本中替换占位符；保留仓库模板。
4. 已有安装先比较和备份。验证参数、链接、Skill 发现和真实 RPC 状态后再启用。

给安装 Agent 的提示：

> 请阅读 RPC开发模式-Agent初始化安装说明.md，先核对本机 OMP 环境，引导我确认模型、模式、上下文整理阈值及安装位置，再初始化并安装 omp-rpc-dev。窗口大小和扩展上下文沿用我的设置，不要修改。不要启动业务开发、改全局默认模型或生产环境；涉及持久化设置和模型测试费用先让我确认。

安装后，在主控窗口调用 `/skill:omp-rpc-dev`，或明确要求使用 `omp-rpc-dev` 开发指定项目。

### 可选：独立交叉审核版

复制完整 `omp-rpc-cross-review` 目录到 OMP 实际 Skills 目录，新开或重新加载后调用 `/skill:omp-rpc-cross-review`。它不依赖或覆盖普通版，也不使用上面的 8 项安装参数表。

调用时提供 `review_provider`（OMP 供应商 ID）、`review_model`（完整模型 ID）、`review_thinking`（该模型支持的思考强度）。缺项时 Agent 必须集中询问；不内置审查默认模型，不自动沿用开发模型。确认值只在同一批次复用，恢复仍复核。不可调思考的模型须经用户明确确认和能力核对，不能默认省略。

审查模型必须不同于主会话及本批所有参与实现的开发模型；供应商或思考档位不同不代表底层模型不同。身份不明时先确认映射，明确相同时重新选择审查模型。保持功能优先、开发期静态审查、完整功能集中冒烟；主会话保留最终裁决与验收，模型意见一致不代替运行证据。

```text
/skill:omp-rpc-cross-review
目标项目：<项目路径>
任务：<完整功能目标>
review_provider: <OMP供应商ID>
review_model: <完整模型ID>
review_thinking: <该模型支持的思考强度>
```

模型可用性、费用授权和参数核对见新版 Skill；仅安装/发现检查无需先指定审查模型，不会自动发起收费审查。


## 功能优先与验证节奏

按架构完成真实功能闭环，再集中冒烟确认跑通，随后按实际使用环境补强必要安全边界，并只回归受影响路径。开发中以静态审查为主；实现切片经静态接收并集成即可继续依赖片，不每改一片就启动服务或重复冒烟。静态接收与功能运行通过分别记录。

审查优先检查功能、架构和数据流；安全建议须有实际暴露面与适用依据，通常放在功能跑通之后处理，不让假想风险衍生出通用安全框架。必要正确性、现有保护、凭据与真实数据隔离及授权仍保留；公网/敏感环境所需保护须在真实暴露前完成。提前运行实验只用于明确的阻塞性不确定性、用户要求或项目强制规则。


## RPC 并发与独立审查

主控可把已解耦的任务派给多个独立 RPC 会话同时执行。先冻结公共契约、依赖和文件/资源所有权，只运行已就绪切片；公共前置实现经主控静态接收并集成后解锁下游，完整功能统一冒烟。同文件写入、共享测试资源及集成操作不能靠多开会话规避冲突。

普通版独立审查按风险启用：跨模块契约、共享状态、事务、权限或复杂集成建议增加审查 RPC；小而独立的改动可由主控审查。交叉审核版必须执行独立异模型审查，不能以低风险或主控自查替代。两版审查会话都只报问题与证据，不直接修改或调度；主控保留需求裁决、派发、集成和最终行为验收责任。

并发上限和费用授权按批次记录，审查会话计入额度。普通版遵循 [普通版 Skill](omp-rpc-dev/SKILL.md) 与 [普通版台账](omp-rpc-dev/references/session-record.md)；交叉审核版遵循 [交叉审核版 Skill](omp-rpc-cross-review/SKILL.md) 与 [交叉审核台账](omp-rpc-cross-review/references/session-record.md)，不要混用参数和门禁。

启动示例：

> 使用 omp-rpc-dev 的 RPC 并发模式。先核对依赖与文件/资源所有权，确认本批并发额度和费用授权；对高风险契约及集成启用独立只读审查。由主会话统一派发和最终验收，不让执行或审查会话递归调度。

离线学习页演示切片静态接收与交接；完整功能才集中冒烟。并发、独立审查和环境加固规则以 Skill 和参考文档为准。本包提供调度方法，不包含自动并发调度器。

## 运行约束

- 主控按完整功能组织实现切片；切片静态接收并集成后推进依赖，完整功能统一运行验收，适用加固完成后才记通过。
- 精确恢复使用原 sessionFile；需要减小上下文时另开会话并读取有效交接。超时写操作不能自动重发。
- 上下文窗口大小和扩展上下文由用户控制，Skill 不规定固定容量或开关，不将其作为安装参数或运行门禁。占用百分比的清理/压缩阈值独立配置。
- RPC 参考来自 OMP 18.8.7；原制包记录核对了 18.9.0 CLI。安装时仍须检查当前版本接口，历史通过不能代替当前验收。
- 提交、推送、创建远程仓库、部署和生产重启需要各自授权；不会因为启用 Skill 自动获准。
