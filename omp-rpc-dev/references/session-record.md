# 开发进度、交接与会话台账

持久状态是长程开发的恢复依据。每个项目/批次在项目外的私有目录保存；沿用项目已有规范，不维护多份重复的状态。项目需要跟踪的非敏感进度可放仓库，但原生 sessions、进程信息与私有证据不要进入公开仓库或公共同步盘。

建议目录：

```text
<private-project-batch>/
  开发进度.md       # 每片状态与主控验收事实
  进度交接.md       # 当前有效现场与精确下一步
  会话台账.md       # RPC 身份、配置、归属与操作回执
  sessions/         # 原生会话，由 OMP 写入
  evidence/         # 脱敏验证证据
```

三份文档各司其职，以切片 id 和证据路径互相引用。进度不复制 transcript，交接不重复完整验收历史。已有一份统一文档时可以用对应章节，不强制拆出三个文件。

## 开发进度模板

```markdown
# 开发进度
项目：<绝对路径>
目标与验收：<有效 Spec 路径/版本>
更新时间：<时间及时区>
批次策略：<最大同时运行 RPC 数，含审查；费用/模型授权；独立审查启用依据与门禁>
基线与集成：<公共契约版本、基线提交或快照哈希清单、集成所有者与顺序>
功能闭环：<功能 id、真实入口到结果、架构/依赖、完成标准、使用环境>
功能状态：<开发中/待冒烟/待修正/待加固/通过；集成版本与运行证据>
集中冒烟：<功能齐备时执行的场景、环境与命令；未运行如实记录>
环境加固清单：<实际暴露面、适用依据、措施、功能后/发布前时点、回归路径；不适用记原因>

| 切片 id | 所属功能/行为 | 依赖 | 状态 | 文件/资源所有权 | 会话及请求 id | 静态审查记录 | 接收基线/未验证项 | 下一动作 |
|---|---|---|---|---|---|---|---|---|
| <id> | <功能 id / 单一行为> | <id 或无> | <状态> | <工作目录/文件/资源/所有者> | <sessionId + RPC id 或未派发> | <候选版本/静态结论/发现处置> | <集成版本；静态接收不等于运行通过> | <具体动作> |

## 当前阻塞
<原因、已核对内容、需要谁作何决定；没有则写无>
## 未验证项
<开发会话报告但主控未确认的结论；没有则写无>
```

切片状态：待派发 → 执行中 → 待静态审查 → 静态接收 / 待修正。修正重新进入执行中，记录新请求和候选版本，再静态复审。静态接收且集成后可解锁依赖片，不要求每片冒烟；不能将其记为功能通过。错误、取消单列；失联/超时记结果未知并保留所有权。契约变化使相关接收结论失效，需重新核对。

功能状态：开发中 → 待冒烟（必要切片均已接收并集成）→ 待修正 / 待加固 / 通过。冒烟失败后修正受影响切片，重新静态接收并定向冒烟；冒烟成功但有适用的必要加固项时进入待加固。完成这些项及受影响路径回归后才记通过；无适用项可由待冒烟直接通过。通过只代表明确的功能范围，不自动授权部署。保留失败证据，不能用静态结论填运行结果。

更新顺序：派发前记所有权、执行中和 sessionId/request id → completed 且 settled 后固定版本 → 静态审查、集成并接收 → 更新交接并解锁依赖片 → 功能齐备后集中冒烟 → 环境加固与定向回归 → 功能通过。无关分支可继续；后置建议不阻塞主链路，当前阶段必要审查与真实阻断缺陷仍须解决。

并发时请求用 `(sessionId, request id)` 唯一关联，不能仅凭请求 id 对应结果。每个审查发现单独记录候选版本、严重程度、定位/证据、未验证项、主控处置依据及修正后的复审结果；候选或契约变化即标记相关审查过期，不能复用旧通过结论。

## 进度交接模板

```markdown
# 进度交接
检查点：<时间/当前切片>
有效目标与 Spec：<路径/版本/段落>
授权：<允许文件、命令、测试资源>
禁止：<提交/推送/部署未授权，以及其他限制>

## 已完成
<分别引用静态接收片、已通过功能和运行证据；不复制全部日志，不混淆两种状态>
## 当前现场
- 用户已有修改：<具体文件/内容，或无>
- 未完成编辑：<文件/符号/实际状态，或无>
- 文件/资源所有权：<每个会话的工作目录、稳定输入基线、写入范围、端口/数据库等资源>
- 最后请求：<逐会话列 sessionId、request id、completed/error/aborted/结果未知、settled 证据>
- 审查现场：<角色与候选版本、有效/过期结论、未处理发现、必要门禁>
- 就绪与阻塞队列：<已解锁片、依赖及阻塞原因，不预排未解锁任务>
- 仍在运行的资源：<归属、用途、处置要求，或无>
- 未验证与阻塞：<具体内容，或无>

## 下一轮调度
- id/目标：<就绪切片列表，每片一个行为；单片时沿用此模板>
- 以下逐片记录：<不得把多个独立契约合成一个任务>
- 输入输出、字段、错误和副作用顺序：<精确契约>
- 允许文件/符号、调用方、禁改范围：<具体列表>
- 静态接收标准与功能冒烟时点：<所属功能、静态检查项、完整闭环场景与允许命令；提前实验须记录具体理由>
- 输出及停止点：<证据要求；完成即停>

## 恢复核对
<需读取的源码、实际工作树状态、原生 sessionFile 引用、模式与占用要求；窗口设置由用户控制>
```

压缩、换会话和计划停止前先更新交接。新会话先核对所有运行会话、所有权、候选版本和门禁，再从就绪队列调度。文档和源码冲突时先查清并修订；摘要不能扩大授权，也不能证明写操作应重放。

## 会话台账模板

```markdown
# 会话台账
项目/批次：<绝对路径及批次名>
OMP：<实际可执行文件和版本>
Profile：<明确值/默认环境；无秘密>
批次并发策略：<引用开发进度中的额度、授权及审查门禁，不维护第二套值>

## 会话 <逻辑名称；每个独立会话重复本节>
角色：<开发/审查/集成；主控唯一派发>
工作目录/基线：<绝对路径、提交或快照哈希清单>
文件/资源所有权：<允许写入范围；审查为只读，复现授权单列>
sessionId：<运行返回值>
sessionFile：<运行返回的精确绝对路径>
控制端：<唯一主控身份、是否持有 stdin>
进程归属：<PID、启动时间、可执行文件、命令行的非秘密部分>
启动约束：<参数及附加边界，不含凭据>
配置证据：<模型、thinking、Fast enabled/active、作用范围；不要求窗口或扩展上下文证据>
工具/扩展：<实际 dumpTools 和授权范围>
当前请求：<id、切片、真实状态、settled/队列>
最近上下文：<实际 percent、检查时间；沿用运行环境计数口径>
上下文操作：<shake/compact 请求 id、结果、操作前后占用>
现场/验收：<引用交接与进度>
中断：<原因、可能副作用、恢复前需核对内容>
```

不得保存凭据、完整 models 配置、生产连接串或可复用令牌。开发输出、会话和截图也可能含私有数据，按当前用户权限保存。

## 用户看到的进度

主控简报只报：运行/就绪/阻塞的切片、审查状态、实际完成和验收、下一动作、是否压缩/换会话。独立开发会话保留历史有助于审查、复盘和恢复；持久会话不等于进程永远运行。主控退出后本方法不保证自主推进。
