# RPC 开发模式

在主控窗口调用 `/skill:omp-rpc-dev` 并说明项目与目标。主控负责需求、Spec、切片、审查和验收；独立 OMP 会话负责指定切片，完成后停止。用户只在主控窗口沟通。执行会话不得递归调用本 Skill 或创建调度会话。

## 0. 初始化门禁

这是可移植安装模板。下列占位符未全部替换、参数未得到用户确认、运行状态未核实前，禁止派发开发任务。完整发布包中的 `RPC开发模式-Agent初始化安装说明.md` 提供详细安装流程；仅持有本 Skill 目录时，按本节初始化步骤执行。配置写入安装副本，保留源模板。

| 参数 | 安装后的约定值 |
|---|---|
| 开发模型完整 provider/id | {{DEV_MODEL}} |
| 思考档位 | {{THINKING_LEVEL}} |
| Fast 是否启用 | {{FAST_MODE_ENABLED}} |
| Fast 是否要求实际 active | {{FAST_MODE_ACTIVE_REQUIRED}} |
| shake 触发百分比 | {{SHAKE_THRESHOLD_PERCENT}} |
| compact 触发百分比 | {{COMPACT_THRESHOLD_PERCENT}} |
| 停止派发百分比 | {{STOP_THRESHOLD_PERCENT}} |
| 压缩后可继续派发的占用上限 | {{RESUME_THRESHOLD_PERCENT}} |

百分比统一使用 0–100 的单位。要求 `0 < RESUME < SHAKE < COMPACT < STOP < 100`。模型和模式须核对真实运行状态；每次启动、恢复、切换模型后重新核对。配置不支持或无法验证时停止，不自动降级或换收费渠道，不修改全局默认模型。

上下文窗口大小和 `extended-context` 由用户及其运行环境控制，不属于本 Skill 的安装参数或准入门禁。主控、开发和审查会话沿用用户配置，不设固定 token 上限、不强制开关、不因无法读取窗口设置而阻止运行，也不为了符合 Skill 自动修改相关配置。

### 最小初始化流程

1. 核对当前 OS、OMP 可执行文件/版本、CLI 帮助、Skills 发现目录及可信项目配置。只查看必要非秘密字段，不读取认证文件或私有模型配置正文。
2. 向用户集中确认上表全部参数、安装位置、配置作用范围与模型费用授权。Fast active required=true 时 enabled 必须 true；模型模式不支持或无法核实时停止。
3. 已有安装先比较并备份，不覆盖未知修改。只在已授权范围落实运行配置；持久化设置另行确认，不改全局默认模型。
4. 将完整 `omp-rpc-dev` 目录复制到实际 Skills 目录，仅替换目标 SKILL.md 中所有 `{{…}}`。核对参数类型、阈值顺序、frontmatter 名称及本地链接；源模板保留占位符。
5. 新开或重新加载 OMP，确认发现本 Skill；按 [RPC 操作参考](references/rpc-control.md) 在私有隔离工作区做无模型调用探针，核对 session、模型、思考/Fast、占用、工具及 settled 状态。
6. 记录参数、安装/备份路径、配置作用范围、实际通过与未验证项。模型请求验收需先获得测试调用及费用授权；任何必要检查失败都不派发业务开发。

## 1. 开始前

1. 用户已选择 RPC 开发方式。核对绝对项目路径、OMP 实际可执行文件/版本、项目规则、现有差异、允许文件与工具、有效 Spec、模型授权。
2. 在项目外的私有持久目录保存原生 sessions、[进度与交接](references/session-record.md)及证据。不同项目/批次不共用 session；Skill 目录不存项目状态或秘密。
3. 先检查旧台账。存在未解决写入者、失联任务或待验收结果时，先核对现场，不新开同文件写入者。
4. 按 [RPC 操作参考](references/rpc-control.md) 连接。先做无模型调用的状态检查，报告真实 sessionId、精确 sessionFile、模型、思考/Fast 模式、占用、工具范围和空闲状态。必要状态无法核实时标记未验证并暂停；窗口及扩展上下文不在此门禁内。

沿用可信项目 Profile，不继承无关生产/书籍 Profile。扩展默认不加载，需要的逐项确认。保留项目规则及开发 Skills。实际 `dumpTools` 需核对；提示词和工具清单不能当作操作系统沙箱。

## 2. 冻结切片

### 功能优先与验证节奏

开发顺序：按已确定架构实现完整功能 → 集成后集中冒烟、确认主链路真实跑通 → 按实际使用环境补强必要安全边界 → 对加固影响的路径定向回归。不得将泛化安全框架、穷举异常或假想攻击防护放在功能主链路之前。

主控先定义功能 id、用户可观察的输入到结果、实际依赖与数据流、完成标准、冒烟场景和使用环境（本机自用/受控内部/公网多用户、数据敏感性及真实副作用）。信息可从项目取得时不重复问用户；未知环境只记录未知，不自动按最高风险环境扩建。完整功能是一个可交付行为闭环，不是整个项目，也不能缩成一个函数。依赖必须真实接通，不用占位返回、mock 或假成功宣称跑通。

实现切片用于分工和上下文控制；功能闭环是运行验收单元。开发期间以静态审查核对架构、契约、调用方和数据流，默认不每片启动服务、跑冒烟、全套测试、构建或格式化。确有编译/类型不确定性时可做最小静态工具检查；不在每次编辑后机械重跑。RPC 状态/settled 检查仍用于调度，不算功能冒烟。

静态审查合格并集成的切片记为“静态接收”，可以解锁同功能依赖片；明确该基线尚未运行验收。全部必要切片完成后，主控对集成版本集中运行完整功能的冒烟，覆盖真实入口、主要成功路径及验收明确要求的关键失败路径。失败时只修正相关范围并定向重跑；不重复无关矩阵。未跑冒烟只能报告静态接收，不能宣称功能完成或可发布。

功能开发阶段只做架构和明确需求必需的正确性/保护：例如用户要求的权限功能本身、真实写入的数据完整性、不可逆操作前的隔离与授权。不得移除已有保护；凭据、生产数据、未授权外部操作不能为提速绕过。功能优先不允许在无必要保护时直接暴露公网。其余加固先记入同一功能的后置清单，逐项写实际暴露面、失败后果、是否适用和处理时点；没有适用依据的建议不实现、不阻塞功能。

冒烟通过后处理实际环境所需加固；不适用项记依据即可。公网发布、多租户或敏感数据使用前，必须落实该环境真正需要的鉴权、隔离等保护。加固完成后只回归受影响行为；有必须加固项未完成时记“功能已跑通、待加固”，不得标记可发布。不要为假设中的未来部署提前铺设通用安全平台。

只有用户明确要求、项目强制规则，或静态审查发现会阻塞后续实现的具体运行不确定性，才提前做最小定向实验；记录问题、必要性和停止点，不能泛化成每片冒烟。审查发现按当前阶段分类：功能/架构缺陷和运行前必需保护可阻断；后置加固建议排期，不占据功能开发主线。


主控先读实际代码。一片只含一个可独立静态核对的实现行为；架构、schema、identity、错误语义及副作用顺序由主控冻结后再交执行会话。

每片必须带：所属功能 id 与阶段；切片 id；目标和 Spec 路径/版本/段落；输入输出及错误分支；允许文件/符号与调用方；禁改范围和用户已有修改；文件所有权；静态接收标准、功能级冒烟场景与允许命令类别；证据类型（静态/已运行/未验证）；完成后停止、不自行推进、不提交或部署的边界。

探索片只读。单一主控拥有 stdin。同工作树共享文件只允许一个写入者。并行必须有独立会话和明确所有权或隔离工作树，主控负责集成。需求不清先核对文件；只有实质取舍或授权缺口才询问用户。

### 2.1 RPC 并发模式

目标是让无依赖、无写入冲突的切片同时执行，减少串行等待；会话数量不等于效率。单片或强耦合任务保持串行，不为凑并发制造切片。

主控在派发前完成：

1. 画出切片依赖图，冻结公共接口、字段、错误语义及功能验收案例。尚未完成的公共实现先作为前置片，由主控静态接收并集成后解锁消费者；实现会话不得各自发明接口，不以逐片冒烟作为默认依赖门禁。
2. 为每片分配允许修改的文件/符号、工作目录、独立 session、外部资源和集成归属。同一工作树按文件独占写入，即使修改不同符号也不同时写同一文件。锁文件、生成文件、公共配置、格式化产物也纳入所有权。
3. 检查读依赖和测试副作用。切片不能把另一会话尚在修改的文件当稳定输入；端口、数据库、缓存、测试账号和构建输出需隔离或串行使用。隔离工作树只能隔离文件，不能消除逻辑依赖及外部资源冲突。
4. 记录本批最大同时运行的 RPC 数、模型/费用授权和审查策略，审查会话占用同一并发额度。未明确授权并发模型调用时先确认；额度内只派发已就绪切片，不擅自扩容或切换收费渠道。每个会话单独通过初始化和状态检查。

需要独立审查时预留审查名额；额度已满则在 settled 边界保存并关闭空闲开发进程，为审查腾出名额，不增加上限。审查或集成积压时优先消化待验收结果，暂停新开发派发，避免所有开发会话占满额度后等待无法启动的审查会话。

主控按就绪队列调度，无须等待无关切片全部完成。就绪要求：前置片已由主控静态接收并集成到当前输入基线（功能已通过时引用已验收版本）；契约与权限明确；无文件/资源冲突；可用会话已 settled，且上下文和并发额度允许。静态基线必须标记尚未运行验收。每个开发会话一次只接一片，不预排未解锁任务。

同一工作树适合读写范围真正分离的切片；需要独立稳定基线时采用隔离工作树或快照，记录各自基线与差异。禁止复制认证文件或私有运行状态；创建提交仍需授权，不能为了 worktree 集成擅自 commit。集成由主控在取得目标文件所有权后执行或单独派发集成片；冲突先核对契约，不让执行会话互相覆盖。

每片返回后按 completed/settled 门禁进入静态审查。主控核对版本、契约及集成结果，记录静态接收、释放所有权、解锁下游，不逐片跑冒烟。功能闭环齐备后统一行为验收。独立分支可继续；同一集成目标的写入串行完成。公共契约变动时暂停受影响消费者，更新 Spec 并重新静态审查；已有功能验收也需按受影响路径复核。

失联、超时或结果未知时保留该片所有权并阻塞其下游；核对进程、资源与副作用后才恢复或转交。只有经确认不共享受影响文件、契约和资源的分支可以继续。主控仍是所有 RPC 的唯一派发者；会话之间不直接调度或转授权。

### 2.2 独立审查 RPC 与主控边界

独立审查按风险启用，不要求每个小改动常驻一个审查会话。跨模块契约、共享状态/并发、事务、权限、安全边界或复杂集成建议启用；低风险且相互独立的改动可由主控审查，记录选择依据。用户或项目规则要求独立审查时必须执行；未获费用授权或会话不可用时报告阻塞，不悄悄省略。

| 角色 | 负责 | 不得代行 |
|---|---|---|
| 主会话 | 需求与 Spec、拆片及依赖、权限和文件所有权、调度、处理分歧、集成与最终行为验收、用户沟通 | 将审查结论当作运行证据或新增授权 |
| 开发 RPC | 在冻结范围内实现，执行指定验证，报告差异、证据与未完成项 | 改公共契约、自行扩范围、指挥其他会话、批准自己的切片 |
| 审查 RPC | 对指定版本核对方案、代码和证据，报告可定位的问题与未验证风险 | 编辑业务代码或正式台账、派发修正任务、改需求或验收标准、决定合并/发布、代用户授权 |

审查会话使用独立 session，默认沿用已授权的模型与运行参数；独立性来自上下文与职责隔离，不要求另选模型。模型或费用范围变化须另行确认。给出必要的 Spec、基线与候选版本、差异、相关调用方、验收案例和证据，不灌入开发会话整份 transcript，也不把开发自评作为事实前提。

审查分三个时点，只做该次范围内的工作：

- **派发前的方案审查**：检查完整功能定义、切片依赖、公共契约、文件/资源所有权和集成顺序是否明确；确认功能级冒烟时点及环境加固范围，不把每个实现片改成独立运行验收任务。只报缺口和具体反例；主控修订后解锁受影响片。
- **切片完成后的静态审查**：优先检查功能实现、架构、调用方和数据流，再核对契约明确要求的错误分支及运行前必需保护。记录静态证据和未验证项，不因没有逐片冒烟阻塞静态接收；环境相关加固建议归入后置清单，不自动扩展实现范围。
- **功能集成后的交叉审查**：检查接口组合、数据流、共享状态及错误传播，确认功能闭环具备运行条件后，由主控集中冒烟。冒烟后按实际环境复核加固清单；不能用单片静态结论代替完整功能验收。

审查对象必须稳定：有提交时记录基线/候选提交；有未提交改动时记录完整输入快照及文件哈希清单。相关调用方和配置也纳入快照。审查期间禁止写入该对象，可让其他会话在不同范围继续开发；候选或契约改变后，相应审查结论失效，重新检查受影响范围。

默认只读工具并核对实际 dumpTools；提示词不构成沙箱。需要运行可能写缓存、数据库或生成文件的复现命令时，由主控先授权并提供隔离环境，不能在活跃开发树里自行验证。报告通过响应返回，只有主控写入正式进度/台账。

每个发现应含：问题 id、所属功能/阶段、严重程度（阻断/非阻断）、候选版本、文件/符号/行号、违反的契约或实际失败场景、证据、建议范围和验证状态。安全建议另列实际环境适用性与处理时点；仅凭“可能不安全”不得阻断。审查结论区分“可静态接收/需修正/审查未完成”和“功能运行未验收/已核对运行证据”，不混写成通过。

主控记录采纳、驳回依据、后置排期或待用户裁定。当前阶段必要审查未完成、阻断缺陷未解决或静态证据不足时，不接收受影响切片；尚未进行功能冒烟和不适用的加固建议不构成开发期阻断。修正由原所有者实施，对新版本复审。功能齐备后必须集中冒烟；运行事实分歧在此阶段验证，提前实验仅按上文例外。需求、费用或风险接受交用户；主控在冒烟及适用加固/回归完成后判定功能通过。


## 3. 执行、审查与记录

- 按请求 id 匹配 JSONL 响应。prompt 受理成功不代表完成；等待同 id 的 prompt_result，保留 error/aborted。
- agent_end 仅代表一轮结束；确认 sessionSettled 或 isSettled，且无队列、异步工作或管理命令，再派下一片、压缩或关闭。
- 开发会话的完成声明只表示切片待审。主控在开发中静态检查改动和调用方，功能实现齐备后集中运行覆盖闭环的冒烟；UI 看实际页面，CLI 看真实交互。构建成功与静态接收不替代功能行为验收。
- 开始前记录执行中；返回后静态审查，接收并集成后推进依赖片。功能状态单独记录开发中、待冒烟、待修正、待加固或通过；运行证据关联功能 id 和集成版本。不要每片重复启动验证环境。
- 超时、失联标记结果未知，检查文件、原生 session、进程和副作用；禁止自动重发写操作。
- 工具授权和交互请求需要明确处理；危险选择不默认接受。用户新指令不能被已排队的下一片越过。

commit、push、创建远程仓库、生产部署或重启分别需要明确授权。删除遵守当地可恢复方式。不得读取/复制认证文件、完整私有模型配置或把凭据写入台账。遇到额度、403 或模型不可用，报告并保留未完成状态。

## 4. 上下文策略

派发前、切片完成后、大量输出后检查 `get_state.contextUsage.percent`，采用当前环境返回的百分比，不另行规定或修改窗口。占用缺失或不可解释时检查当前版本接口，仍无法取得可靠值就暂停，不能当作 0%。

| 条件 | 空闲安全边界动作 |
|---|---|
| 达到 {{SHAKE_THRESHOLD_PERCENT}}% | /shake 清理已读工具输出；记录真实结果与新占用 |
| 达到 {{COMPACT_THRESHOLD_PERCENT}}%，或 shake 后余量不足 | 先写交接检查点，再 compact；确认成功和实际占用 |
| 达到 {{STOP_THRESHOLD_PERCENT}}% | 不派发新开发片；保存交接、压缩或换新会话 |
| 压缩后低于 {{RESUME_THRESHOLD_PERCENT}}%，且下一片有余量 | 核对 Spec、授权、所有权和现场，再继续 |
| 压缩不足、明显降速、阶段变化或历史混乱 | 保留旧 session，交接后开全新会话 |

多个条件同时满足时采用更严格动作。阈值属于主控调度策略，OMP 不保证自动执行。长回合可能越线，以小切片和有限读取控制增量；不在文件写入/验证中途强行压缩。不循环压缩，不把失败记为完成。

原生 session 保留开发过程，开发进度记录验收事实，交接文档保留下一步。压缩后重新载入有效 Spec、授权、所有权和相关源码。维护好这些材料通常有助于 GPT 压缩后保持开发状态，但摘要可能遗漏，恢复时仍需核验；不承诺零遗忘。

## 5. 恢复和换会话

精确恢复沿用旧 sessionFile，用于继续历史；全新会话读取交接，用于减小上下文。两者不要混用。新会话不灌入整份旧 transcript。

Eval 内核丢失不代表旧进程停止。核对本批次进程身份与活动，不能凭 PID 重新接管 stdin，不能杀光 Node/OMP。旧写入者尚在运行时不得启动第二个写入者。无法确认现场时暂停接管并报告。

恢复时重新附加权限边界，核对项目/sessionId、配置、队列、外部资源与上次请求结果。交接与源码冲突时先核实并修订文档，不重做已完成改动，也不扩大授权。

主控只向用户报告当前片、实际完成与验证、未解决问题、必要授权、压缩或换会话情况。主控停止后不保证继续调度；本 Skill 不安装常驻守护服务。
